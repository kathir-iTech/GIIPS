Architecture

  • New file: ai-engine/classification/tamil_fallback.py
  • Detection: is_tamil_text() — returns True if ≥20% of alphabetic chars are Tamil Unicode (U+0B80–U+0BFF)
  • Matching: tamil_keyword_classify() — counts substring hits per category, picks winner, caps confidence at 55%
  • Tagging: Response includes "method": "tamil_keyword_fallback" vs "ml_model" / "heuristic_fallback"
  • Safety: If no keyword match → falls through to existing ML model (doesn't make it worse)
  • Scope: Only activates for predominantly Tamil text — English/Tanglish path untouched

2. Embedding Model Swap

Swap: all-MiniLM-L6-v2 (English-only, 6-layer) → paraphrase-multilingual-MiniLM-L12-v2 (50+ languages, 12-layer)

Affects clustering (DBSCAN) and duplicate detection (NearestNeighbors with cosine). Does not touch TF-IDF classifier or keyword fallback.

3. Deploy Risk Assessment

MetricOLD (MiniLM-L6)NEW (multilingual L12)
Model weights~80 MB~470 MB
Disk cache~90 MB~713 MB
Transformer layers612
Load time (cached)~10 s~12 s
Encode speed~100–150 texts/s~46 texts/s
Estimated RAM at runtime~150 MB~800–1000 MB
⚠️ High Risk for Render Free ($0) & Starter ($7/mo) tiers (512 MB RAM)
The model alone needs ~500–700 MB of heap. Combined with FastAPI, TF-IDF classifier, DB connections, and uWSGI workers, this will likely cause OOM kills or heavy swap thrashing.
Render PlanRAMVerdict
Free / Starter ($7/mo)512 MB❌ Will OOM
Professional ($19/mo)1 GB⚠️ Tight — use single worker + lazy-load
Professional+ ($38/mo)2 GB✅ Comfortable

Mitigations if stuck on 512 MB

  1. Lazy-load the SentenceTransformer only when clustering/dup-detection is called (not at server boot)
  2. Set OMP_NUM_THREADS=1 and MKL_NUM_THREADS=1 to limit parallel-inference memory overhead
  3. Use a single uWSGI worker process (workers=1)
  4. Point SENTENCE_TRANSFORMERS_HOME to a persistent volume so the 713 MB download doesn't re-download on every restart
