### 5.4 Role Enforcement Mechanisms

1. **`get_current_user()` dependency** (`routes.py:59-73`): Extracts JWT from httpOnly cookie or `Authorization` header, decodes, looks up User in DB. Applied to all auth-required endpoints via `Depends(get_current_user)`.

2. **`get_executive_user()` dependency** (`routes.py:1300-1304`): Verifies `role == "Executive"`. Applied to all admin endpoints.

3. **Inline role checks:** Used on merge (line ~766), split (line ~854), status update (line ~981), escalate (line ~1033), escalated incidents list (line ~1072), ward complaints (lines ~1146-1149). Pattern: `if db_user.role not in [...] raise HTTPException(403)`.

4. **Rate limiting:** `check_auth_rate_limit` (5/min) on auth endpoints via `Depends`. `check_complaint_rate_limit` (10/min) on complaint submission and merge/split.

5. **Registration restriction:** `@gov.in` emails blocked from public registration. Only Executives can create government accounts via `/admin/officers`.

## 6. FEATURES

### 6.1 Citizen Features

- **Self-registration**: Email/password signup with `@gov.in` domain block. Fields: full_name, email, password, phone, district, ward.
- **Multi-step complaint submission wizard** (`/citizen`):
  - Step 1: Personal details (pre-filled from profile)
  - Step 2: Complaint title + description
  - Step 3: Location — address search via OSM Nominatim (Tamil Nadu bounded, 500ms debounce)
  - Step 4: Photo upload — JPG/PNG, max 5MB, client-side compression to <1MB (1600px max, quality 0.8)
  - Step 5: Review all entered data
  - Step 6: Submit — polls `/complaints/{id}/status` every 1.5s until completed or failed (120s timeout)
- **My Complaints** (`/my-complaints`): Searchable, filterable list of own complaints with status, category, confidence, duplicate indicator.
- **Complaint Detail** (`/complaint/:id`): Photo gallery, meta grid (location, ward, date, category, department), AI category/confidence, merge reason, linked incident details, full timeline with priority history.
- **Profile management** (`/profile`): View/edit full_name, email, phone, district, ward with edit/save toggle.
- **Notifications**: Real-time polling (45s interval) for: complaint created, merged into incident, status changes, aging warnings. Dropdown with unread count, mark-all-read, click-to-navigate.
- **Language switching**: English ↔ Tamil (தமிழ்) toggle stored in localStorage (`giips_lang`). Full 916-key i18n coverage for both languages.

### 6.2 AI/ML Features

#### 6.2.1 Complaint Classification

- **Primary model:** TF-IDF vectorization + LogisticRegression, trained on NYC 311 dataset (50k rows, mapped to 5 Tamil Nadu categories)
- **Model accuracy:** 57.1% (acknowledged as Phase 1)
- **5 output classes:** Road Infrastructure, Sanitation, Street Lighting, Waste Management, Water Supply
- **Heuristic fallback:** Keyword-based classification for 10 categories (Roads, Water Supply, Garbage, Drainage, Streetlights, Electricity, Public Health, Pollution, Traffic) with confidence 0.75
- **Explainability:** Returns reason string, supporting factors (keyword matches), and method used (ML/heuristic/Tamil)
- **Training pipeline:** Standalone `train_classifier.py` at root + `ai-engine/classification/train.py`

#### 6.2.2 Duplicate Detection

- **Primary model:** SentenceTransformer (`all-MiniLM-L6-v2`) + NearestNeighbors (n_neighbors=5, cosine distance)
- **Fallback:** Jaccard keyword overlap on tokenized text (used when sentence-transformers/torch unavailable)
- **Confidence formula:** `text_similarity × 0.6 + location_proximity × 0.3 + category_match × 0.1`
  - Location proximity: geodesic distance via `geopy.distance`, scaled [0,1] (1000m = 0)
  - Category match: 1.0 if same, else 0.0
  - Threshold: `dup_conf > 0.8` → flagged as duplicate
- **FAISS indices:** Optional FAISS index building (flat/IVF/HNSW) for faster similarity search
- **Impact metrics (claimed):** 99.97% duplicate reduction via SBERT, 49.7% via keyword fallback; estimated 99,970 officer-minutes saved

#### 6.2.3 Clustering

- **Primary model:** ComplaintClusterer — SBERT all-MiniLM-L6-v2 + DBSCAN (eps=0.17, min_samples=2)
- **Fallback:** Text-prefix bucketing (first 50 chars) — very simplistic
- **Backend `ClusteringService._fallback_cluster()`** currently used: groups by first 50 chars of text
- **Evaluation:** Silhouette, Calinski-Harabasz, Davies-Bouldin, ARI, NMI metrics available

#### 6.2.4 Tamil Language Support

- **Tamil keyword fallback** (`tamil_fallback.py`): Phase 1.5 temporary keyword-based classification for Tamil text
- **Intended replacement:** IndicBERT / LaBSE multilingual embeddings (Phase 3 — deferred due to memory constraints on free tier)
- **Full Tamil UI:** 916-key i18n JSON with complete Tamil translation of all UI strings

#### 6.2.5 Priority Scoring

- **PriorityEngine** (`priority/priority.py`): 4 weighted factors:
  - Cluster size: 30% — sigmoid(complaint_count), normalized [0,1]
  - Complaint age: 25% — exponential decay based on days open
  - Category severity: 25% — lookup: Water=0.90, Road=0.85, Sanitation=0.80, etc.
  - Location importance: 20% — keyword match: school=1.0, hospital=0.95, market=0.85
- **Final score:** `weighted_sum × 100`, clamped [0, 100]
- **Labels:** Critical (90+), High (75-89), Medium (50-74), Low (0-49)
- **PriorityRulesEngine** (`priority/rules.py`): 8 rule adjustments:
  - Safety Critical: +20 (injury, accident, hazardous keywords)
  - School Proximity: +15 (school, playground, daycare in location)
  - Hospital Proximity: +12 (hospital, clinic, medical in location)
  - Water/Public Health: +10 (water, sewage, contamination keywords)
  - Long Standing: +8 (>21 days unresolved)
  - Large Cluster: +7 (>20 complaints)
  - Recurring: +5 (recurring issue detected)
  - Minor Issue: -5 (cosmetic categories)
- **EscalationPolicy:** 4 levels — Immediate (90+), Urgent (75+), Standard (50+), Routine — with response times, notification rules, and category-specific recommended actions

## 7. KNOWN LIMITATIONS / DEFERRED ITEMS

### 7.1 ML Model Limitations

| Issue | Status | Notes |
|-------|--------|-------|
| Classification accuracy 57.1% | **Accepted (Phase 1)** | Trained on NYC 311 data mapped to 5 TN categories. Planned: IndicBERT/LaBSE with TN-specific training data in Phase 3. |
| No Tamil NLP model deployed | **Deferred (Phase 3)** | `tamil_fallback.py` uses keyword matching. IndicBERT/LaBSE reverted during Phase 1.5 for memory reasons (free tier constraints). |
| SBERT/torch commented out in requirements.txt | **Deferred** | Sentence-transformers and torch removed from default `pip install` to keep free-tier memory under 512MB. Falls back to Jaccard keyword overlap. |
| Clustering service uses text-prefix fallback | **Unimplemented** | `ClusteringService._fallback_cluster()` groups by first 50 chars of text — no real ML clustering in the live service. The `ComplaintClusterer` (SBERT + DBSCAN) exists in `clustering/cluster.py` but is not wired into services.py. |
| Duplicate detection requires data loading | **Performance note** | Loads all recent complaints (up to 1000) into memory each time. Could be slow with large datasets. |
| Dataset is NYC 311, not Tamil Nadu | **Known gap** | No real Tamil Nadu complaint dataset available for training. Synthetic data generated via `generate_tn_dataset.py`. |

### 7.2 Backend Limitations

| Issue | Status | Notes |
|-------|--------|-------|
| Inline pipeline blocks startup | **Accepted** | `asyncio.create_task()` runs during lifespan — if it takes too long (10k+ complaints), Render's free tier 15s startup timeout may kill the process. Mitigated by batch processing. |
| No message queue in production | **Deferred** | arq worker deprecated. Inline `asyncio.create_task()` is not durable — if the process crashes mid-pipeline, that complaint is lost. Redis-based job queue planned for Phase 3. |
| No write-through caching | **Deferred** | Redis used only for rate limiting and complaint status — no query result caching. Every dashboard load hits the DB. |
| No database migrations (Alembic) | **Deferred** | Schema changes handled by `ALTER TABLE ... ADD COLUMN` in startup with try/except. Not safe for production. Column additions are applied on theory rather than versioned migration. |
| Audit log only tracks officer operations | **Partial** | Only officer create/disable/enable, department view, system health view are logged. Complaint submission, incident merge/split/status/escalate are NOT audited. |
| Backfill silently crashes on hex incident numbers | **Fixed 14 July 2026** | `int(max_row.split("-")[1])` fails on `INC-A1B2C3` format. Now uses UUID-based IDs. |
| `WorkerSettings` references wrong module path | **Broken** | `arq ai_engine.backend.worker.WorkerSettings` — the actual module is at `ai-engine/backend/worker.py`, which Python would import as `backend.worker`, not `ai_engine.backend.worker`. The deprecated worker path is incorrect. |

### 8.2 Frontend (Vercel)

- **Framework:** Vite + React SPA
- **Build:** `npm run build` → `tsc -b && vite build` → outputs to `dist/`
- **Deploy:** Vercel auto-detects Vite, applies `vercel.json` rewrite (`/*` → `/index.html`)
- **Environment variable:** `VITE_API_BASE_URL=https://giips-backend.onrender.com`
- **Domain:** Custom domain or `giips.vercel.app`
- **Free tier limits:** 100GB bandwidth, 100 deployments/day, 3000 build minutes/month

### 8.3 Backend (Render)

- **Runtime:** Docker — `python:3.11-slim-bookworm`
- **Process:** `uvicorn ai-engine.backend.app:app --host 0.0.0.0 --port 8000 --log-level info --workers 1`
- **Healthcheck:** `curl -fsS http://localhost:8000/health` every 30s
- **Free tier limits:** 512MB RAM, 0.1 CPU, 15s startup timeout, sleeps after 15min idle
- **No `render.yaml` or `Procfile` — Render auto-detects the Dockerfile**

### 8.4 Docker Compose (Local Development)

### 8.6 Database

- **Development:** SQLite at `ai-engine/data/giips.db`
- **Production:** PostgreSQL via `DATABASE_URL`
- **ORM:** SQLAlchemy 2.0+ with auto table creation (`Base.metadata.create_all`) on every startup
- **Schema migrations:** Manual `ALTER TABLE` in startup (not safe for production — see §7.2)
- **Seed data:** `seed_demo_users()` creates 9 demo users; `seed_default_executive()` creates collector@gov.in; `seed_synthetic_data(10000, 0.15)` generates 10k complaints + 150 incidents

### 8.7 Startup Sequence (lifespan in `app.py`)

```
1. Load classifier model (TF-IDF + LR)
2. Initialize PriorityEngine
3. Create/verify database tables (Base.metadata.create_all)
4. ALTER TABLE complaints ADD COLUMN address (silent if exists)
5. ALTER TABLE users ADD COLUMN department (silent if exists)
6. Seed demo users (idempotent)
7. BACKFILL: ward redistribution + incident linking
8. Seed default executive (collector@gov.in)
9. Backfill complaint user_ids
10. Migrate old department names
11. Ensure outputs directory exists
12. Log S3 storage availability
13. Initialize Redis pool (arq, for status tracking)
```
